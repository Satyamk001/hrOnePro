Build a single-page web app called "Attendance Insights" using React 19 + Vite + TailwindCSS.

CONTEXT / INPUT FORMAT
The user has attendance data exported from a biometric/HR system as a JSON array. Each object 
represents one day and looks like this:

{
  "employeeId": 0,
  "shiftId": 1,
  "timeIn": "08:36",
  "timeout": "18:01",
  "presentStatus": null,          // e.g. "Late" or null
  "calculatedWorkingHours": "09:25",  // HH:MM string
  "isLeave": 0,                   // 0 or 1
  "shiftStartTime": "09:30",
  "shiftEndTime": "18:30",
  "shiftCode": "GEN",
  "attendanceDate": "2026-07-01T00:00:00",
  "updatedFirstHalfStatus": "P",   // P, FL, EL, WO, HD, etc.
  "updatedSecondHalfStatus": "P"
}

The app should accept a paste of this JSON (one day, a few days, or a full month — the data length 
is variable and unknown ahead of time). Don't assume 30 entries; compute everything dynamically 
from whatever is pasted.

CORE FEATURES

1. INPUT
   - A large textarea (or a modal) where the user pastes raw JSON.
   - A "Load Data" / "Analyze" button. Validate JSON; show a clear inline error if parsing fails 
     or the shape doesn't match expectations (missing keys, etc.) rather than crashing.
   - Support pasting a single object OR an array of objects.
   - Persist the last-pasted data in memory (component state) so switching between views doesn't 
     require re-pasting. No backend, no localStorage — pure client-side, in-memory only.

2. STATUS CLASSIFICATION
   Derive a clean per-day status from updatedFirstHalfStatus / updatedSecondHalfStatus / isLeave:
   - "P" + "P" → Present (full day)
   - "WO" + "WO" → Week Off
   - "FL" / "EL" (or isLeave = 1) → Leave (distinguish Full Leave vs Earned Leave if both codes appear)
   - Half-day combos (e.g. "P" + "FL") → Half Day
   - presentStatus === "Late" → flag as a late arrival regardless of the above
   - timeIn/timeout both null and not WO/Leave → treat as missing/absent, flag distinctly

3. TIME MATH (all in HH:MM, convert to minutes internally)
   - Standard shift duration = shiftEndTime - shiftStartTime (e.g. 09:00 for a 09:30–18:30 shift)
   - Per-day extra/deficit = calculatedWorkingHours - standard shift duration 
     (positive = overtime, negative = shortfall). Only compute this for days actually worked 
     (skip WO/Leave days).
   - Total working hours across the loaded period (sum of calculatedWorkingHours on worked days)
   - Total extra time and total shortfall (sum separately, both as running totals)
   - Average work duration per worked day
   - Earliest/latest clock-in and clock-out across the period
   - Count of late arrivals (based on presentStatus === "Late" AND/OR timeIn > shiftStartTime — 
     show both if they differ)

4. SUMMARY DASHBOARD (top of page, card grid)
   - Total days loaded
   - Present days / Week-offs / Leaves / Half-days / Missing punches (counts)
   - Total working hours (formatted like "182h 45m")
   - Total overtime / extra hours given
   - Total shortfall hours (time owed vs standard shift)
   - Average working hours/day (worked days only)
   - Punctuality: number & % of late arrivals
   - Longest and shortest working day (date + duration)

5. VISUALIZATIONS (use recharts)
   - Bar chart: daily working hours vs standard shift hours (grouped/overlaid bars), one bar per 
     date, so over/under time is visually obvious
   - Line chart: daily clock-in and clock-out times plotted against the standard shift window, 
     to visualize punctuality trends across the period
   - Pie/donut chart: breakdown of day types (Present, WO, Leave, Half-day, Missing)
   - Optional: weekly aggregation view if the loaded range spans multiple weeks (avg hours/week)

6. DAY-BY-DAY TABLE
   - Sortable table below the charts: Date, Day of week, Status, Time In, Time Out, Worked Hours, 
     Shift Hours, Extra/Deficit (color-coded green for overtime, red for shortfall), Late flag.
   - Highlight rows for late arrivals or shortfalls in working hours.

7. UX / DESIGN
   - Clean, modern dashboard aesthetic (card-based layout, subtle shadows, rounded corners), 
     Tailwind only, no inline styles.
   - Fully responsive — should work well on both desktop and mobile.
   - Empty state before data is pasted: a friendly prompt with a short example of the expected 
     JSON shape.
   - Loading/parsing should be instant (no artificial delay) since it's client-side only.
   - Handle edge cases gracefully: single-day input (just show the summary cards + table, skip 
     charts that need multiple data points, or show a single-bar version), missing fields, 
     null timeIn/timeout, unusual status codes not in the known list (show them as "Other" rather 
     than crashing).

8. TECH
   - React 19, Vite, TailwindCSS, recharts for charts, date-fns (or plain JS Date) for date handling.
   - Single-file or a few well-organized components — doesn't need to be over-engineered, this is 
     a personal utility tool, not a production SaaS product.
